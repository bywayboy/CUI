# CUI 主题编辑器设计方案

> 目标：可视化编辑 CUI 的 Light/Dark 全量主题令牌，实时预览，并生成可直接
> 回贴到 `src/ui/ui_theme.c` 的 `theme_apply_preset()` 代码。
>
> 产物：`bin\cui_theme_editor.exe`（CUI Theme Studio）、
> `src/ui/ui_theme_edit.*`（令牌/工程/代码生成工具）、
> `tests/ui_theme_edit_test.c`（headless 断言）。

---

## 1. 目标与约束

### 1.1 要解决的问题

- 内置配色散落在 `theme_apply_preset()` 的 68 个 `t->xxx = 0xAARRGGBB` 里，
  调一次色要改十几处、切主题对照、再跑一遍全部样例看效果。
- 语义角色（primary/warning/success/error/neutral）由颜色派生，不能只看
  色值判断最终效果，必须放到真实组件上预览。
- 73 个令牌一次全铺出来，新用户不知道先改哪个；从"想改按钮颜色"到找到
  `btnPrimary` 的路径太长，需要一条从界面元素反查令牌的入口。
- 主题是运行时全局广播的，编辑器本身也应立刻换肤，避免"预览和实际不一致"。

### 1.2 硬约束

- 纯 C11、0CRT、Direct2D/DWrite，与库其它样例共用 `UiApp` 壳。
- 不引入新的运行时主题 API；导出物仍是"替换预设函数"，应用侧零改动。
- 令牌必须与 `UiTheme` 结构真实偏移一致，不能手抄一份容易漂移的列表。
- 200% DPI 下三栏布局不重叠、列表/拾取器/预览均可操作。

## 2. 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 生成物形态 | 替换预设函数 | 应用侧无新 API；颜色/圆角与内置完全同构；可继续被 `SetColors` 覆盖 |
| 编辑范围 | 68 色 + 5 圆角全量 | 派生角色只读；所有可视令牌都能改，避免"改不到"的死角 |
| 双模式 | 单模式编辑 + 另一模式对照 | 屏幕空间有限；每行右侧显示对照色块，可"复制到另一模式" |
| 上手路径 | 基础视图 15 项 + 预览点选 | 先给常用项中文短名，再从组件反查令牌；高级视图保留全量，零能力损失 |
| 预览定位 | 悬停描边 + 点击选中 | 所见即所得；命中按最小矩形优先，按钮/输入框内层可精确落到填充色 |
| 随机配色 | 三张候选卡 + 锁组 + 单步撤销 | 一次看到 3 套完整方案再选，比反复单步随机更可控；锁住喜欢的主色/中性色再重抽 |
| 随机范围 | 均衡（相近/互补/三角/分裂互补） | 既有变化又不像纯随机那样刺眼；对比度不达标的方案直接重试 |
| 启动状态 | 恢复上次工程 | 调色是跨会话的；工程文件损坏/缺失时回退内置预设 |
| 持久化位置 | exe 同目录 `theme_editor.palette` | 免注册表、免用户目录；开发时随 bin 一起清理 |

## 3. 数据模型

### 3.1 令牌快照

```c
#define UI_THEME_TOKEN_COUNT  68
#define UI_THEME_RADIUS_COUNT 5
#define UI_THEME_FIELD_COUNT  (UI_THEME_TOKEN_COUNT + UI_THEME_RADIUS_COUNT)

typedef struct UiThemeSet {
    UiColor color[UI_THEME_TOKEN_COUNT];
    float   radius[UI_THEME_RADIUS_COUNT];
} UiThemeSet;
```

`UiThemeSet_Read/Apply` 通过令牌表的 `offsetof(UiTheme, key)` 读写字段。
新增令牌只改 `UiTheme` 与 `ui_theme_edit.c` 的表，编辑器列表、工程文件、
代码生成和测试自动跟随；表顺序同时是界面顺序。

### 3.2 令牌表

```c
typedef struct UiThemeTokenDesc {
    const char *key;     /* 结构字段名, 同时是工程文件键 */
    const char *group;   /* 列表分组: 基础/强调/控件/设备面板/... */
    const char *hint;    /* 中文描述, 也参与搜索 */
    unsigned    offset;  /* offsetof(UiTheme, key) */
    int         kind;    /* COLOR / RADIUS */
} UiThemeTokenDesc;
```

- 测试断言：key 非空且唯一、颜色 key 与圆角 key 不重复、`offset` 与结构
  偏移一致、表大小等于常量。
- 分组顺序：基础 10、强调 6、控件 3、设备面板 13、卡片/控件 7、安装器 7、
  面板/主按钮 8、次级按钮 7、进度 3、Toast 4，共 68；圆角单独一组"几何"。
- 基础视图另有一张 `UiThemeBasicDesc basic_table[15]`：`{ key, 中文短名,
  展示分组 }`，只存 key，索引由令牌表反查缓存，避免两处偏移漂移；
  `UiTheme_BasicField(n)` / `UiTheme_IsBasicField(field)` /
  `UiTheme_FieldLabel(field)` / `UiTheme_FieldGroup(field)` 供编辑器和测试共用。

### 3.3 派生角色只读

`theme_bind_roles()` 由 `blue/orange/green/danger/btnBg` 派生
`primary/warning/success/error/neutral` 的 base/hover/press/soft/text/border。
编辑器不直接编辑角色，但每次写回都调用新公开的 `UiTheme_DeriveRoles()`，
保证预览与运行时一致；右侧预览的 5 张角色色卡用于检查派生结果。

## 4. 模块划分

```
src/ui/ui_theme_edit.c   令牌表 / 读写 / 工程文件 / HEX / 对比度 / 代码生成 / 抽卡生成器
src/ui/ui_theme_edit.h   公开声明（无渲染依赖, headless 可测）
samples/theme_editor.c   UiApp + 三栏界面 + 拾取器 + 预览 + 文件对话框/剪贴板 + 抽卡面板
tests/ui_theme_edit_test.c  headless 断言
```

`ui_theme_edit` 不依赖 Gfx/D2D，只依赖 `UiTheme` 与 Windows 文件/格式化 API，
因此测试可以直接跑，不需要创建窗口。

## 5. 工程文件格式

```text
cui-theme 1
[light]
page=F7F9FF
frameHi=70FFFFFF
...
windowRadius=14
[light 之后是 [dark]，键相同
```

- 首行必须精确为 `cui-theme 1`，否则 `UiThemeSet_Load` 返回 0。
- 颜色：6 位 = 不透明（alpha 补 FF），8 位 = 带 alpha；大小写均可。
- 圆角：十进制浮点，输出时省略 C 后缀（`14` / `21.5`）。
- 未知键、未知 section、空行忽略；缺行保留调用方当前值。
- 保存缓冲区不足返回 -1，且保证末尾 NUL；加载按 192 字节行切分，超长行截断。
- 自动保存是"每次有效修改 + 关闭时"整份重写；文件小（约 2.4 KB），无并发问题。

## 6. 代码生成

```c
/* generated by cui_theme_editor 2026-11-15 17:36 */
static void theme_apply_preset(UiTheme *t, UiThemeId id)
{
	t->themeId = id;

	if (id == UI_THEME_DARK) {
		t->page = 0xFF121722;
		/* … 68 色 … */
		t->windowRadius = 14.0f;
		/* … 5 圆角 … */
		return;
	}

	t->page = 0xFFF7F9FF;
	/* … 68 色 … */
	t->windowRadius = 14.0f;
	/* … 5 圆角 … */
}
```

要点：

1. 颜色固定 `0x%08X`，保留 alpha；曾出现测试按 6 位构造期望值导致误报，
   现在测试也用独立的 8 位格式化函数。
2. Light/Dark 圆角分别在各自分支输出。早期版本在分支外只写 Dark 一份，
   Light 单独调整的圆角会被静默丢弃；headless 断言现在同时检查两套值。
3. 缩进与 `ui_theme.c` 现有代码一致，生成后可直接整体替换函数体。
4. 时间戳来自 `GetLocalTime`，`wsprintfA` 不支持 `%f`，圆角用整数格式化。

## 7. 编辑器界面

### 7.1 布局（1280×840，最小 1120×700）

```
┌ Header: 标题 + Light/Dark + 重置本模式 + 复制代码 + 导出代码 ┐
├ 左：令牌列表 336 ┤ 中：当前令牌 340 ┤ 右：组件预览 自适应 ┤
└ 状态提示（列表底部） + 全局键盘/搜索提示（窗口底部） ┘
```

### 7.2 左侧列表

- 标题右侧"基础/高级"分段按钮：基础视图只显示 15 个常用令牌，行内是
  "中文短名 · key"（如"窗口背景 · page"）；高级视图显示全量 73 项，行内
  只有 key。右上角"显示 n / 73"随过滤实时更新。
- 基础视图的 15 项来自 `ui_theme_edit.c` 的 `basic_table`（12 色 + 3 圆角），
  按"外观/文字/交互/几何"重排分组；`UiTheme_BasicField/IsBasicField/
  FieldLabel/FieldGroup` 对外暴露映射，测试与编辑器共用同一张表。
- 搜索框：匹配 key / 分组 / 中文描述，也支持"分组 key"组合串；搜索或
  "仅显示已改"生效时不再套基础视图过滤，匹配到的高级令牌也会出现。
- "仅显示已改"复选框：与内置快照比较，计数实时更新。
- 每行：当前模式色块、key、另一模式对照色块、修改圆点；圆角令牌画圆角
  示意块而不是色块。
- 分组头只在首行/跨组时出现；基础视图行距 28（15 项一屏放满、不出现滚动
  条），高级/过滤视图行距 30，组头 24。基础视图切回时若当前选中项不在
  15 项内，自动改选第一项，避免"选中项不可见"。
- 色块先画棋盘（透明度可见），再填色，最后用 `border` 与 `text3` 混合描边
  ——纯白令牌在浅色卡片上也能看见边界。

### 7.3 中间编辑面板

- 标题显示"分组 · 中文短名"（基础令牌）或"分组 · key"，与列表/预览提示一致。
- 颜色：色块、HEX 文本、alpha 百分比、内置/已修改标记、HEX 输入框、
  HSV 方块（白→透明、透明→黑两层渐变）、色相条、透明度条、对比度。
- 拾取器使用 `Ui_StateInstant` + `Ui_SetPressPoll`，按下后按 `mouseX/Y`
  连续更新，拖动过程每帧写回并保存；`mouseDown` 结束后清空拖动状态。
- 圆角：圆角盒子、0–24 滑杆、常用值 chips（0/4/6/8/10/12/16）、修改标记。
- 底部：仅当项被修改时显示"恢复此项"；"复制到 Dark/Light"始终可用
  （两模式一致时显示禁用的文本按钮）。

### 7.4 右侧预览

覆盖文本层级、主/次/文字/删除按钮、Switch/Checkbox/Slider、输入框、
进度条、Toast、列表行、分页、5 个语义角色色卡。预览是一个独立
`UiScrollView`，短窗口下可滚动；编辑器本身使用当前编辑中的主题绘制，
所以改 `page/card/text` 等令牌时整窗立即变化。

预览同时是**点选入口**：

- 每个可编辑元素在绘制时登记 `{矩形, 字段}` 到 `hits[]`；命中查询取"包含
  光标且面积最小"的矩形，保证按钮外框落到 `btnPrimaryBorder`、内层落到
  `btnPrimary`，输入框外框/内层/文字分别落到 `inputBorder/inputBg/hint`。
- 悬停：元素描 2px 主色轮廓；令牌名画在"组件预览"标题右侧（头部在滚动
  裁剪区之外），避免遮挡内容；鼠标离开时清除。
- 点击（按下与抬起都在同一命中区域才算）：切到对应令牌、列表用
  `ScrollTo(..., 0)` 立即滚到该行。若当前是基础视图且令牌不在 15 项内，
  自动切高级视图，状态行提示"已切到高级视图 · 中文名 · key"。
- 命中检测用窗口原始坐标做，不依赖 `UiContext` 的 z 序，所以预览里的按钮/
  开关仍能正常点击，两者互不抢占。

### 7.5 交互与状态

- Light/Dark 切换会重建 HSV/HEX 状态并整窗失效。
- 键盘：搜索框/HEX 框聚焦时输入优先；否则 ↑↓ 切换令牌并 `EnsureVisible`，
  Enter 应用 HEX，Esc 退出输入。
- 状态行显示"已选择 中文名 · key""已切到高级视图 · …""HEX 已应用/无效"
  "已恢复本项内置值""已复制到 Dark""已导出: 路径""已取消导出"等。
- 列表与预览每帧调用 `UiScrollView_Tick`，`animating` 回调返回 `Busy()`；
  否则滚轮只更新 target、offset 不动（实现时踩过，已修）。
- 点选/切视图的定位是导航行为，用 `ScrollTo(..., 0)` 立即落位；键盘上下
  选择仍保留平滑滚动。

### 7.6 抽卡（随机配色）

头部"抽卡"按钮打开模态面板，一次给出 3 套完整候选（方案 A/B/C）：

- 每张卡上半部是 Light 缩略预览、下半部是 Dark 缩略预览，含正文/次级文本、
  输入框、主按钮、进度条、3 个语义圆点与强调色块；卡片右上角显示该方案的
  seed（`#%08X`），便于复现。
- 顶部"锁定组"三枚 chip：主色 / 中性色 / 语义色。锁住的组从当前工程原样
  拷贝（无当前工程时用模板），不参与重抽；锁组随批次保留。
- 底部：批次 seed + "n 组锁定 · 生成器自动校验对比度"；"撤销上次抽卡"
  （无记录时禁用）/ "重抽" / "关闭"。
- "使用这套"把候选写入当前工程并保存，记录一份单步撤销快照，然后关闭面板。
- 键盘：Esc 关闭、R 重抽、U 撤销、1/2/3 直接应用第 A/B/C 套；面板打开时
  吞掉其余按键/字符。点击面板外关闭。
- 面板用 `Ui_SetModal` 阻断底层控件；命中检测在窗口原始坐标上进行（与预览
  点选同一套最小矩形策略），保证 chip/按钮在模态下仍可交互。

生成器（`UiThemeGen_Palette`）不是逐令牌乱随机，而是"模板 + 受控变换"：

1. 一个 seed 同时驱动 Light/Dark，两套配色同源，避免"亮色是这套、暗色
   完全另一套"。
2. 令牌按族变换：中性族整体换色相并保持原亮度；主色族按配色方案偏移色相、
   调饱和度/明度并封顶亮度；强调色取次色相；语义色只做 ±3.5° 微扰与饱和
   缩放，保持"绿=成功/橙=警告/红=危险"的识别；主按钮文字按模板极性选择。
3. 配色方案在相近（26–60°）、互补（170–190°）、三角（115–130°）、分裂
   互补（145–165°）中随机，并避开红/橙/绿语义色相与主色相。
4. 生成后按内置的 12 组前景/背景配对校验对比度（正文 4.4、次级 2.3、
   提示 1.25 等），被锁组完全覆盖的配对跳过；不达标换 seed 重试（最多 6 次），
   全部失败返回 0 且不改动输出。
5. 5 个圆角不随机，始终沿用当前工程；锁组从当前工程拷贝。
6. 连续 seed 先做 6 次 xorshift 预热，避免小种子首个输出过小导致颜色扎堆。

## 8. 0CRT 细节

- `wvsprintfA` 只支持整数/字符串：浮点显示用 `fmt_fixed` 手写定点，
  圆角格式化用整数十分位。
- 文件读写 `CreateFileW/ReadFile/WriteFile`；工程路径 = exe 目录 +
  `theme_editor.palette`。
- 导出用 `comdlg32!GetSaveFileNameW`，默认文件名 `theme_apply_preset.c`，
  过滤器"源文件 (*.c)"；对话框在绘制回调外打开，避免渲染重入。
- 剪贴板 `OpenClipboard/EmptyClipboard/GlobalAlloc/SetClipboardData(CF_UNICODETEXT)`，
  代码先 UTF-8→UTF-16。
- `rpcndr.h` 的 `#define small char`：不要用 `small` 作标识符（测试里踩过）。

## 9. 验证

### 9.1 headless（7574 断言）

- 表完整性：68/5、key 唯一、颜色/圆角不冲突、首个偏移与结构一致。
- 基础视图：15 项、索引合法且互不重复、中文名/分组非空、与 `basic_table`
  的 key 逐项一致、4 个分组都出现、高级令牌 `toastBg` 不在基础表、
  越界下标返回 -1。
- 读写往返：68 色 + 5 圆角逐项相等；派生角色跟随 `blue/btnHoverBg`。
- 工程文件：头/section/键、往返、未知键与缺行容错、空/错误头返回 0、
  小缓冲区 -1 且 NUL 结尾。
- 代码生成：函数签名、`themeId`、Dark 分支、`return` 唯一、136 个 8 位色值
  逐项匹配、两套圆角、时间戳、小缓冲区 -1。
- HEX：6/8 位、`0x` 前缀、空白、奇数长度/非法字符/NULL 拒绝；格式化
  省略 FF alpha，小缓冲区返回 0。
- 对比度：黑白 ≈21、同色 ≈1、中灰 ≈1.9、半透明前景合成。
- 字段修改判定：颜色/圆角下标、空指针、越界。
- 内置预设一致性：从 `UiTheme_SetTheme` 读出 Light/Dark，导出后逐项
  能在生成代码中找到，且已发布的 `btnHoverBg/btnPressBg/dark page` 不变。
- 抽卡生成器：同 seed 确定性、seed 0 可复现、非法参数返回 0 且不改输出、
  alpha 保留、圆角取自当前工程；主色/中性色/语义色三组锁逐一验证只锁该族、
  三组全锁时等于当前工程、`keep=NULL` 回退模板；Light/Dark 主色相 ≤8°、
  语义色相分离（红/橙/绿两两 ≥20–25°）；200 个种子逐对检查组 `tg_pairs`
  可读性下限；48 个种子至少产生 24 种不同主色（防止颜色扎堆）。

### 9.2 4K@200% 截图

3840×2160 @200%（窗口 2560×1680 物理像素）逐项验证：

- Light/Dark 首屏、页脚完整、三栏不重叠；
- 基础视图 15 项一屏放下（无滚动条）、行内中文短名、`显示 15 / 73`；
  高级视图 `显示 73 / 73`、原分组完整；

## 10. 已知限制与取舍

- 派生语义角色只读：要改 primary 悬停/按下，改 `blue/btnPrimaryHover/...`
  等源令牌；这保持运行时派生逻辑唯一。
- 手工编辑没有撤销栈：误改可用"恢复此项/重置本模式"回内置值；只有"抽卡"
  提供单步撤销（保留抽卡前的一份快照）。工程文件每次修改即覆盖，未做多版本历史。
- 列表虚拟化未做：68+5 行全量布局/绘制，2K/4K 下开销可忽略；若令牌数
  增长到数百行，可接 `UiScrollView` 的 Cull/行缓存。
- 工程文件是全局单份（exe 旁），不支持多套命名方案；需要多套时可复制
  bin 目录或后续扩展文件名参数。
- 编辑器不写回 `ui_theme.c`，只生成文本；避免运行时改写源码的权限/格式风险。
